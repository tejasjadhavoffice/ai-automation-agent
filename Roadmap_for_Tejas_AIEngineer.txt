AI Automation Agents – 1 Month Roadmap
Candidate: Tejas
Track: AI Engineer

Goal: Build a production-ready AI automation agent while demonstrating the core competencies expected of an AI Engineer — LLM fundamentals, prompt engineering, agent architecture, tool design, and production-grade system thinking.

How this roadmap works:
•	The automation agent is the project. AI engineering is what gets assessed.
•	Each week adds a layer to the agent AND tests a new AI engineering skill.
•	Evaluation is split: 50% on the working agent, 50% on AI engineering concepts.


Evaluation Focus (AI Engineer Competencies)
[ LLM & Prompt Engineering ]
•	LLM internals: tokens, context window, temperature, top-p
•	Prompt design: system prompts, few-shot examples, chain-of-thought
•	Function/tool calling and structured JSON output parsing

[ Agent Architecture ]
•	Reasoning loops and the ReAct pattern
•	Task decomposition and goal-directed planning
•	Memory: short-term (context window) vs long-term (vector store / persistent state)
•	Tool design: when to use tools vs when to reason directly

[ Systems & Production Thinking ]
•	Error handling, retries with exponential backoff
•	Observability: structured logging and tracing agent steps
•	Idempotency: workflows that can safely re-run
•	Agent guardrails: validating outputs before acting on them

[ Automation Engineering ]
•	Clean, modular Python code
•	Workflow design: sequential vs parallel execution
•	Debugging agent failures: reading logs, isolating the broken step

[ Process ]
•	Weekly code review and verbal walkthrough
•	GitHub commit consistency across all 4 weeks
•	Written design decisions on architecture choices

Week 1 – LLM Fundamentals + First Automation Agent
Theme: Understand how LLMs work, then build the simplest possible working agent using that knowledge.

AI Engineering Concepts to Learn
•	How LLMs work: tokens, context window, temperature, top-p
•	Prompt design: system prompt vs user prompt, role separation
•	Zero-shot vs few-shot vs chain-of-thought — when each works best
•	Function/tool calling: how to define a tool and parse the LLM's tool call response
•	JSON structured output: enforcing schema on LLM responses
•	API error handling: rate limits, timeouts, retries with exponential backoff

Automation Agent Coding Tasks
•	Write Python code that sends a structured prompt to an LLM and parses the response
•	Implement tool calling logic: User request → Identify action → Call tool → Return result
•	Build one simple automation: given a text request, agent identifies the right tool and executes it
•	Compare zero-shot vs few-shot prompting for the same task — document the difference
•	Add error handling: all API calls wrapped in try/except with retry logic

Deliverables
•	Working single-tool automation agent
•	Prompt experiment notebook: zero-shot vs few-shot with written observations
•	Error handling demo: show graceful recovery from a simulated API failure

Evaluation
[ AI Engineering ]
•	Can explain tokens, context window, and how temperature affects output
•	Can explain why their system prompt is structured the way it is
•	Understands the difference between tool calling and regular prompting

[ Agent ]
•	Tool calling works end-to-end
•	Structured JSON output is parsed correctly

[ Pass/Fail ]
•	Agent runs without crash and handles at least one API failure gracefully
•	LLM responses are validated as JSON before being used
•	Prompt notebook shows genuine experimentation with written conclusions

Week 2 – Agent Architecture + Reasoning Loop
Theme: Move from a single tool call to a real agent loop. Understand how agents plan, reason, and chain actions.

AI Engineering Concepts to Learn
•	Agent architecture: the difference between a pipeline and an agent loop
•	ReAct pattern (Reason + Act) — the industry standard agent loop
•	Task decomposition: how to break a complex goal into executable steps
•	Short-term memory: managing what stays in the context window across steps
•	Loop termination: how to detect when the agent is done vs stuck

Automation Agent Coding Tasks
•	Refactor the Week 1 agent into a proper ReAct loop:
◦	while task_not_complete: reason → choose action → execute → observe result
•	Implement task decomposition: agent breaks a high-level request into sub-tasks
•	Log every reasoning step: what the agent decided and why
•	Add loop termination logic: max steps, completion detection, stuck detection
•	Implement context trimming: keep conversation history within token limits

Deliverables
•	ReAct-pattern automation agent that handles multi-step tasks
•	Reasoning step log showing agent decisions with justifications
•	Architecture diagram of the agent loop

Evaluation
[ AI Engineering ]
•	Can explain the ReAct pattern and why it outperforms a linear pipeline for complex tasks
•	Can explain what happens when the context window fills up and how they handle it
•	Can describe how to detect and break an infinite agent loop

[ Agent ]
•	Multi-step task completes end-to-end through the reasoning loop
•	Every action has a logged reason

[ Pass/Fail ]
•	ReAct pattern is implemented — not a linear pipeline
•	Agent cannot run more than a defined max number of steps (loop guard in place)
•	Reasoning log is readable and shows genuine decision-making

Week 3 – Production Thinking + Automation Workflows
Theme: Build multiple automation workflows while applying production-grade engineering: guardrails, observability, idempotency, and error recovery.

AI Engineering Concepts to Learn
•	Agent guardrails: validating LLM outputs before acting on them
•	Idempotency: designing workflows that are safe to re-run
•	Observability: structured logging, request tracing, step-level monitoring
•	Memory management: short-term context vs long-term persistent state
•	Failure modes: what can go wrong in an agent and how to design defensively

Automation Agent Coding Tasks
•	Build 3 automation workflows:
◦	1. Automated report generation from raw data
◦	2. Data analysis workflow with summarisation
◦	3. Task scheduling and delegation
•	Add guardrail checks to each workflow: validate LLM output before acting
•	Make workflows idempotent: re-running should not cause duplicate side effects
•	Add structured logging to every step: input, output, decision, timestamp
•	Simulate one failure scenario per workflow — show graceful degradation

Deliverables
•	3 working automation workflows
•	Architecture diagram covering all 3 workflows
•	One documented failure simulation per workflow with recovery behaviour

Evaluation
[ AI Engineering ]
•	Can explain what guardrails are and give an example of one failing without them
•	Can define idempotency in the context of their workflows
•	Understands the difference between short-term memory (context) and persistent state

[ Agent ]
•	All 3 workflows run end-to-end
•	Failure simulations handled gracefully — no unhandled exceptions

[ Pass/Fail ]
•	Every workflow has at least one guardrail check
•	Re-running any workflow twice does not produce duplicate outputs
•	Structured logs capture every step

Week 4 – End-to-End Production System + Design Assessment
Theme: Complete the automation system and demonstrate AI engineering maturity through a design review, code walkthrough, and production readiness assessment.

Final Project: Production Automation Agent
Build an agent that completes tasks like: "Generate weekly sales insights"

•	Accepts natural language requests and decomposes them into steps
•	Executes at least 3 distinct tool types: e.g., file read, API call, data computation
•	Runs as a ReAct loop with full reasoning logs
•	Handles ambiguous input: asks a clarifying question before executing
•	Applies guardrails at every output-to-action boundary
•	Runs with full observability: every step logged and traceable

AI Engineering Assessment Tasks
•	Write a 1–2 page system design document covering:
◦	Why you chose this agent architecture over alternatives
◦	How you would scale this to handle concurrent automation requests
◦	What monitoring and alerting you would add in production
◦	How you would handle LLM provider outages or degraded performance
◦	What guardrails you would add before deploying this to real users
•	Code walkthrough: explain every architectural decision verbally during review
•	Debugging test: be given a broken agent log and diagnose the failure

Deliverables
•	Complete automation agent codebase
•	System design document (1–2 pages)
•	GitHub repo with consistent commits across all 4 weeks

•	System design document submitted and discussed
